这是什么What it is

一个围绕某个网站（中心域名，如 soundbuttons.click）寻找真实可用外链目标并做缺口分析的工具。它把「见过」和「已拥有」严格分开，四层数据各司其职：

A tool that finds real, usable backlink targets for one site (the center domain, e.g. soundbuttons.click) and analyses the gap. It keeps "seen" strictly apart from "owned" across four layers:

层Layer 含义Meaning 谁来写Written by
候选池Candidate pool 历史上发现过的目标站点，只是"见过"的清单Targets discovered so far - merely "seen" 每次分析自动并入Every analysis run
已有外链库Acquired library 你真实已拿到的外链域名（GSC / Ahrefs / 自建记录）Domains you genuinely own (GSC / Ahrefs / your own records) 你导入You import it
投放台账Delivery ledger 逐条投放记录，是"已交付"的唯一事实源One record per placement - the single source of truth for "delivered" 你认领并推进状态You claim and advance it
缺口 gapGap 在池里、但既没导入为已有、也没上线投放的目标In the pool, yet neither imported as acquired nor live in the ledger 系统算出Computed
核心认知：见过 ≠ 已拥有。只有导入为已有、或在台账里带着证据标为 live，才会从缺口里扣掉。 Core idea: seen is not owned. Only an acquired import, or a ledger entry marked live with evidence, removes a target from the gap.

标准工作流（五步闭环）Standard workflow (five-step loop)

  1. 定中心域名 + 关键词：顶部是可输入下拉，列出已知域名并标注 池/种子/竞品反链 数量（`.cc` 与 `.click` 不会再混）；也可直接输入新域名。分析页填品类词（不是品牌词），逗号分隔。不同域名的数据完全隔离。 Set the center domain and keywords: the top field is a typable dropdown listing known domains with pool/seed/comp-link counts (no more mixing .cc with .click); typing a new domain still works. Then category terms (not brand names), comma separated. Each domain has isolated data.
  2. 跑分析：点「分析」。候选来自该域名的种子库（seeds/seed-<域名>.json）、可选的 Bing 实时发现，以及竞品外链站（seeds/competitor-links-<域名>.json，按证据准入、不受关键词门限）。结果按优先级（相关性 + 权威 + 可获取）排序。 Run the analysis: click Analyze. Candidates come from that domain's seed library (seeds/seed-<domain>.json), optional live Bing discovery, and competitor backlink sites (seeds/competitor-links-<domain>.json, admitted by evidence and exempt from the keyword gate). Rows are ranked by priority (relevance + authority + obtainability).
  3. 看池子、算真缺口：到「外链池」看统计卡与目录树。还没导入已有外链时，所有候选都会被算成缺口，这是正常中间态。 Read the pool: open Pool for the stat cards and the type tree. Before any import, every candidate counts as gap - that is the expected intermediate state.
  4. 导入已有外链：把真实已有域名（每行一个）贴进「导入已有外链」，缺口立即重算；误导入可撤销，候选不丢。 Import acquired backlinks: paste the domains you really own (one per line) and the gap recalculates immediately. A wrong import is reversible and never loses candidates.
  5. 把候选变成已交付：在台账里认领投放位 → 推进 registered → claimed → submitted → live；标 live 必须给落地 URL 与验证方式。不要的域名用「永久排除」。 Turn candidates into deliveries: claim a slot, then advance registered → claimed → submitted → live. Marking live requires a landing URL and a verify method. Use "exclude forever" for domains you never want.

投放位状态机与排除规则Placement states and exclusion rules

状态路径：registered → claimed → submitted → live，另有 lost（失效待复核）、rejected / error（终态）。

State path: registered → claimed → submitted → live, plus lost (expired, pending review) and the terminal rejected / error.

  • live 需要证据：landing_url + verify_method（如 manual_check），只"点了提交"不算。live needs evidence: landing_url plus verify_method (e.g. manual_check); "I submitted it" alone is not enough.
  • live 永久锁定：同一个投放位不会再被推荐，避免重复投放。Live is locked forever: the same slot is never recommended again.
  • 进行中幂等：重复认领同一投放位不会产生两条记录。In-progress is idempotent: re-claiming a slot never duplicates it.
  • 同域名节奏窗口：90 天内该域名已有 live / submitted，会拦下新的认领并给出原因。Per-domain cadence: if the domain already has a live/submitted slot within 90 days, new claims are blocked with a reason.
  • 排除：显式排除的域名或精确投放位永久剔除；误操作可在台账里撤销。Exclusion: an excluded domain or exact slot is dropped permanently; a mistake can be undone from the ledger.
  • 竞品域名不是外链站：竞品及其子域在候选阶段整行剔除——不做 HTTP 校验、不入池、不计入候选/有效/缺口，只在统计卡下方单独计数。A competitor is not a backlink site: competitor hosts and their subdomains are dropped at the candidate stage - no HTTP probe, no pool entry, no candidate/valid/gap count, only a separate line under the stat cards.
  • 竞品的外链站才是候选：由离线 host 图 harvest 生成（tools/competitor_backlinks.py → seeds/competitor-links-<域名>.json），每行带 via_competitors 与边数证据；类型按域名推测，投放前人工复核。Sites that link to a competitor ARE candidates: produced by the offline host-graph harvest (tools/competitor_backlinks.py → seeds/competitor-links-<domain>.json); each row keeps via_competitors and edge counts as evidence, with the type guessed from the hostname for review.

今日队列（日配额 + 冻结批次）Daily queue (quota + frozen batch)

curl -s "http://127.0.0.1:8787/api/queue?domain=soundbuttons.click&date=2026-11-15"
# explicit top-up only: &refill=1

「每天 100 个」是工作配额，不是产量：当天冻结一批、领走即出队、不自动补齐。返回里的 supply_gap = quota − batch_size，缺口只能靠跑分析（队列条上的「补候选」）或补 harvest 文件来填，不会用重复域名凑数。 quota_gate 是配置值，quota_used/quota_left 是硬闸门口径：超过配额的领取会被服务端拒绝（409）， 从池里单条「选用」也一样。配额日按 UTC+8 结算。date 由客户端传本地日期，所以「今天」是你的今天。 "100 a day" is a work quota, not a production rate: the batch is frozen for the day, claimed rows leave it, and it never refills itself. supply_gap = quota − batch_size is the part inventory cannot cover — close it with a fresh analysis (the Get more button) or a harvest file, never with duplicates. quota_gate is the configured ceiling; quota_used/quota_left is the gate: claims beyond it are rejected (409), including single claims from the pool. The quota day rolls at UTC+8. The client sends its local date, so "today" is your today.

配额设置与白名单Quota settings and whitelist

# hard daily ceiling (1-2000, stored per center domain)
curl -s -X POST http://127.0.0.1:8787/api/settings \
  -H 'Content-Type: application/json' \
  -d '{"center_domain":"soundbuttons.click","daily_quota":100}'

curl -s "http://127.0.0.1:8787/api/whitelist?domain=soundbuttons.click"

# add / remove (URLs and "www." are normalized; junk is rejected)
curl -s -X POST http://127.0.0.1:8787/api/whitelist \
  -H 'Content-Type: application/json' \
  -d '{"center_domain":"soundbuttons.click","domains":"example.com, https://www.foo.com/x","action":"add"}'

curl -s -X POST http://127.0.0.1:8787/api/whitelist \
  -H 'Content-Type: application/json' \
  -d '{"center_domain":"soundbuttons.click","domains":"example.com","action":"remove"}'

白名单是「记录留着但不算数」：域名仍在池里（可随时移出），但不计入累计发现、已拥有、缺口、类型分布、互链占比与今日队列， 对它领取投放位会被拒绝。每条记录在界面上都有「加入白名单 / 移出白名单」按钮；池页顶部可批量粘贴。 A whitelist entry means "keep the record, don't count it": the host stays in the pool (removable at any time) but is excluded from discovered, acquired, gap, type distribution, reciprocal ratio and the daily queue, and claiming a placement on it is refused. Every record has an Add/Un-whitelist button; the Pool tab accepts a bulk paste.

导入已有外链（预览 / 导入 / 撤销）Import existing backlinks (preview / import / undo)

# 1) preview: reports the gap delta, writes nothing
curl -s -X POST http://127.0.0.1:8787/api/placements/import \
  -H 'Content-Type: application/json' \
  -d '{"center_domain":"soundbuttons.click","source":"ahrefs-2026-11","dry_run":true,
       "text":"https://www.reddit.com/r/foo/comments/abc/\nhttps://listicle.example/best"}'

# 2) import for real (accepts URLs, bare hosts, or a pasted CSV export)
curl -s -X POST http://127.0.0.1:8787/api/placements/import \
  -H 'Content-Type: application/json' \
  -d @import.json    # {"center_domain":"...","source":"gsc","text":"..."}

# 3) undo only the rows this import created for those hosts
curl -s -X POST http://127.0.0.1:8787/api/placements/import \
  -H 'Content-Type: application/json' \
  -d '{"center_domain":"soundbuttons.click","remove":true,"text":"reddit.com"}'

导入不是打个标记，而是把每一行写成一条 state=live 台账记录（verify_method=import:<来源>， 未实地探测）。池内域名会从缺口里减掉，池外域名只记账不塞进池子，并受 90 天同域节奏保护。 不吃日配额：一次粘 500 行也不会顶死当天的闸门。自身域名、竞品、白名单、已排除与重复会自动跳过并计数。 An import is not a flag: every row becomes a state=live ledger record (verify_method=import:<source>, never probed). In-pool domains leave the gap, out-of-pool hosts are booked without entering the pool and fall under the 90-day per-domain cadence. No daily quota is consumed — a 500-row paste cannot close the day's gate. Your own domain, competitors, whitelisted hosts, suppressed hosts and duplicates are skipped and counted.

数据与备份Data and backup

  • 每个域名一份存储：data/store-<中心域名>.json（候选 domains、已有 acquired_domains、台账 placements、排除 suppressions）。One store per domain: data/store-<center_domain>.json (domains, acquired_domains, placements, suppressions).
  • 调度配置 data/schedule.json、运行历史 data/schedule_runs.json、渠道开关 data/channels-<域名>.json。Scheduler config data/schedule.json, run history data/schedule_runs.json, channels data/channels-<domain>.json.
  • 这些都在 data/ 下，不进 git；本地与线上（Fly 卷）各自独立。All of it lives under data/ and is not in git; local and production (Fly volume) are independent.
  • 种子库 seeds/seed-<域名>.json 进 git 并随镜像烘焙，属受控输入，改动需要提交发布。Seed libraries seeds/seed-<domain>.json are in git and baked into the image; changing one means committing and deploying.
  • 备份：整份复制 data/ 即可。Backup: copy the whole data/ directory.

常见问题FAQ

分析点了没结果？Analyze returns nothing?

九成是该域名没有种子库，或线上 Bing 出口被挡。先确认 seeds/seed-<域名>.json 是否存在；线上数据中心出口常被 Bing 拒绝，属正常，种子库是主通道。

Usually the domain has no seed library, or live Bing is blocked from the server's egress. Check that seeds/seed-<domain>.json exists; data-centre egress is often refused by Bing, which is normal - seeds are the primary channel.

为什么候选全都算缺口？Why is every candidate a gap?

因为还没有导入已有外链库。导入之后缺口才会缩小；池里有 51 条而缺口 51，说明确实一条都还没标记为已有。

Because nothing has been imported as acquired yet. Until then every candidate counts. A pool of 51 with a gap of 51 simply means nothing is marked as owned.

导入错了能撤回吗？Can a wrong import be undone?

能。池页的「取消已拥有」或 /api/store/unmark-existing，候选本身不会丢。

Yes - use "unmark acquired" on the Pool page or /api/store/unmark-existing. Candidates are never lost.

台账里 live 加不上？Cannot mark a slot live?

必须同时提供落地页 URL 与验证方式，缺一不可；这是为了防止把"联系过"错记成"已上线"。

Both a landing URL and a verify method are required - this prevents "contacted" from being recorded as "published".

不同网站的数据会混吗？Do different sites share data?

不会。每个中心域名独立存储、独立种子作用域；切换域名即整体隔离。

No. Each center domain has its own store and seed scope; switching the domain isolates everything.

域名输入框变红了？Why is the domain box red?

输入的不是一个完整域名（缺少点或后缀太短）。补全后自动恢复，中心域名不会被半成品字符串覆盖。

The value is not a complete hostname (missing a dot, or the TLD is too short). Finish typing and it recovers; the center domain is never overwritten with a partial string.

定时任务会一直跑吗？Does the scheduler keep running?

它是服务器进程内的线程，服务器停就停。要 7×24 常驻需 systemd / pm2 / nohup；Fly 上机器休眠期间不触发。

It is a thread inside the server process, so it stops with the server. For 24x7 use systemd / pm2 / nohup; on Fly nothing fires while the machine is asleep.
